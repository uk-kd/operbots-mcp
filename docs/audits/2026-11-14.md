# Аудит MCP и совместимости с панелью — 14 ноября 2026

Репозиторий даёт MCP-клиенту доступ к пользовательской панели operbots по персональному API-токену. Сервер запускается отдельным stdio-процессом, работает от имени пользователя и оставляет проверку прав API. Проверка рассчитана на интерактивные вызовы нескольких локальных клиентов, а не на публичный многопользовательский MCP-шлюз.

Ветка: `audit/panel-sync-2026-11-14`. База: `8f7eb74`. Контракт сверялся с текущим соседним `operbots`, включая миграцию `0040_ai_jobs`. Новых зависимостей нет; изменения не опубликованы.

## Подтверждённые проблемы и исправления

1. **UUID мог выбрать другую запись по имени — исправлено.**
   - Где: `src/context.ts:161`, вызывающие селекторы в `bots.ts`, `knowledge.ts`, `people.ts`.
   - Ситуация: искомого UUID больше нет, но другая запись названа этой строкой. После поиска ID прежний код переходил к поиску по имени, что могло изменить или удалить другую запись.
   - Исправление: общий `pickByName` трактует UUID только как идентификатор и возвращает 404 при отсутствии. Есть регрессионный тест; обычные имена и неоднозначность проверяются прежними тестами.
   - Последствие без исправления: запись могла быть выбрана вопреки явно заданному ID.

2. **Timeweb и пять новых узлов сценария отклонялись схемой MCP — исправлено.**
   - Где: `src/enums.ts:54`, `src/tools/ai.ts`, `src/tools/flows.ts:116`.
   - Ситуация: панель уже принимает `kind=timeweb` и `trigger.ai_job`, `action.ai_transcribe`, `action.ai_speech`, `action.ai_video`, `action.ai_batch`; MCP отказывал до HTTP.
   - Исправление: перечисления синхронизированы. Проверено совпадение всех 56 NodeKind и 39 Permission; подключаемых видов ИИ — 6.
   - Последствие без исправления: нельзя создать соответствующее подключение или сохранить сценарий из актуальной панели.

3. **В MCP отсутствовали 16 действующих операций ИИ — исправлено.**
   - Где: новый `src/tools/ai-media.ts`, подключённый через существующий `aiTools`.
   - Ситуация: нельзя запросить модели, выполнить потоковую пробу, синтез/расшифровку, управлять файлами и Batch/Video задачами, хотя эти операции уже есть в панели.
   - Исправление: добавлены 16 инструментов, использующих прежний HTTP-клиент, обработку ошибок и разрешение подключения. Для задач нужен явный ключ идемпотентности; скрытых повторов нет. Для `user_data/messages` целевые модели проверяются до HTTP/чтения файла. Batch допускает 50 МиБ, другие загрузки — 20 МиБ, скачивание — 100 МиБ без перезаписи.
   - Последствие без исправления: текущие сценарии ИИ нельзя полностью обслуживать через MCP. Платные и внешние запросы исключены из read-only, включая GET кандидатов сверки.

4. **Каталог терял параметры и возможности режимов ИИ — исправлено.**
   - Где: `src/tools/catalog.ts:193`.
   - Ситуация: API возвращает `capabilities`, `options_schema`, `modes`, но отображение MCP выбрасывало их. Пользователь видел Timeweb без сведений о Gateway/Agent и `access_id`.
   - Исправление: поля выводятся вместе с каталогом. Добавлен регрессионный тест; реальные данные каталога проверены через HTTP→PostgreSQL. `ai_test` также сохраняет возвращаемый API `response_id`.
   - Последствие без исправления: помощник вынужден угадывать параметры и предлагать операции, не поддерживаемые выбранным режимом.

5. **Настройки обязательных уведомлений выглядели изменяемыми — исправлено.**
   - Где: `src/tools/notifications.ts:36`, `scripts/backend-smoke.mjs`.
   - Ситуация: запрос отключения `moderation.*` получал «Настройки сохранены», хотя API принудительно оставлял их включёнными. Старый smoke считал первый вид отключаемым и падал на новом каталоге.
   - Исправление: MCP явно отказывает в отключении обязательного уведомления до запроса. Smoke выбирает необязательный вид и отдельно проверяет отказ для обязательного.
   - Последствие без исправления: ложное ожидание об отключении и устаревший интеграционный тест.

6. **Шаблоны дел были недоступны через MCP — исправлено.**
   - Где: `src/tools/catalog.ts:110`, `src/tools/cases.ts:153`.
   - Ситуация: `/cases/templates` и `CaseCreate.template_key/include_examples` существуют в панели, но MCP создавал только пустое дело и терял переданные поля.
   - Исправление: `operbots_catalog what=case_templates`, параметры создания `template_key` и `include_examples`; попытка передать их при редактировании явно отклоняется. Существующие сигнатуры инструментов сохранены.
   - Последствие без исправления: результат создания отличается от запрошенного и возможностей панели.

## Архитектура, ООП, ошибки и производительность

`AuthManager` отвечает за профиль и токен, `OperbotsApi` — HTTP и файлы, `Context` — выбор дела/бота и короткий кэш. Инструменты объявляются данными и регистрируются одним проходом. Новая подсистема использует эти границы; добавлять иерархию классов инструментов или второй клиент API не требуется.

Проверены общий таймаут, запрет HTTP redirects с секретами, ошибки 401/403/409, сохранение `revision/version`, недопустимые и неоднозначные цели, read-only, маскирование секретов, атомарная запись профиля и эксклюзивное создание скачиваемого файла. Повреждённый или незавершённый SSE, включая ошибку после `done`, не выдаётся как успешный ответ. Права и ограничения квоты остаются у панели.

Скачивание уже потоковое и ограничено 100 МиБ; оно не было переписано. Загрузка остаётся ограниченной по размеру и использует существующий multipart. Новые списки файлов/задач читают сохранённые данные одним запросом и не создают циклы опроса провайдера. SSE-проба возвращает итог целиком; прогрессивные MCP-уведомления не добавлялись. Нагрузочные измерения не проводились, поэтому ускорение в процентах не заявляется.
