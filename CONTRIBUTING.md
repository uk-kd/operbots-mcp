# Разработка

```bash
npm install && npm run build
claude mcp add operbots-dev -- node ./dist/index.js
```

Требуется Node 20 или новее. `npm run typecheck` — проверка типов без сборки,
`npm run watch` — пересборка на лету.

Что где лежит:

```
src/index.ts      разбор команды: сервер MCP или действие в терминале
src/server.ts     сборка сервера, регистрация инструментов, окно входа
src/auth.ts       вход и поддержание доступа с ротацией токена
src/credentials.ts хранилище доступа и блокировка файла
src/context.ts    разбор дел и ботов по имени, короткий кэш
src/tools/        инструменты по разделам панели
scripts/          разнос версии и сборка плагина
plugins/          плагин Claude Code вместе с собранным сервером
```

`npm run build` собирает дважды: `tsc` даёт обычный `dist/` для пакета npm, а
`scripts/pack-plugin.mjs` сворачивает всё в один файл
`plugins/operbots-mcp/dist/index.js` с вшитыми зависимостями. Этот файл **едет в
репозиторий**, и это осознанно: Claude Code берёт плагин прямо отсюда, а `npx` из
запуска убран — на нём установка и ломалась. Править там нечего, он собирается из `src/`.

Инструмент объявляется данными, а не обращениями к SDK: имя, описание, схема
входа, признак `read | write | danger` и обработчик. Признак уходит в подсказки
MCP — клиент спрашивает разрешение на `danger` — и им же отбирается набор для
режима «только чтение». Новый инструмент достаточно добавить в массив своего
раздела и подключить раздел в `src/server.ts`.

Описания инструментов и текст ошибок читает модель: они на русском и объясняют
не только что делает вызов, но и чем это обернётся — что заменяется целиком,
что необратимо, что расходует чужие лимиты.

# Выпуск

Одна команда:

```bash
git tag v0.1.2 && git push origin v0.1.2
```

Метка запускает `.github/workflows/release.yml`: номер берётся **из неё** и
разносится по `package.json` и плагину, проходит проверка типов и запуск
собранного сервера со сверкой версии, пакет уходит в npm с отметкой о
происхождении, появляется релиз GitHub с архивом и заметками, а версия
возвращается коммитом в `main` — иначе плагин Claude Code показывал бы номер
прошлого выпуска.

Номер в `package.json` править руками не нужно: источник правды — метка.
Повторный запуск по той же метке не падает: опубликованная версия пропускается,
существующий релиз получает свежий архив.

Секретов не требуется. Право публиковать выдаётся по OIDC через «Trusted
Publisher» на странице пакета в npm; доверие привязано к этому репозиторию и к
файлу `release.yml` — переименуете файл, поправьте привязку, иначе публикация
откажет. Действию нужны права `contents: write` и `id-token: write`, а в
настройках репозитория — Actions → General → Workflow permissions → Read and
write.

Каталог плагина (`.claude-plugin/marketplace.json`, `plugins/operbots-mcp/`)
живёт здесь же и отдельной публикации не требует: Claude Code берёт его прямо
из репозитория.
